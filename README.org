#+TITLE: org-reading-list

Maintain a bibliographic reading list in Org mode — one heading per
book, full bibliographic data in property drawers, subjects as tags,
reading status as TODO keywords.

The property schema follows BibTeX field names wherever an equivalent
exists, so the list exports to a =.bib= (ol-bibtex, citar, ebib) with
little translation, while library-world identifiers — LCCN, OCLC, LC
and Dewey classification, local call numbers, holdings — ride along in
their own properties. The full schema, with format conventions and
crosswalks to MARC 21, BibTeX/biblatex, and the Open Library API, is
documented in [[file:doc/reading-list-schema.org][doc/reading-list-schema.org]].

* Features

- Capture an entry from [[https://openlibrary.org][Open Library]] by ISBN, by Open Library
  edition id, or by pasting an openlibrary.org URL — pre-ISBN books
  work via their edition id.  ISBNs Open Library lacks (e.g. 979-8
  self-published books) fall back to the Library of Congress catalog.
  Pre-ISBN books can be captured by catalog card number
  (=LCCN:61-10539= — hyphenated form fine, it is normalized).
- Enrich entries from the Library of Congress catalog (SRU/MARCXML):
  backfill LCCN, OCLC number, LC and Dewey classification, the MARC
  520 summary as =:ABSTRACT:=, and harvest 650/651 subject headings as
  Org tags.
- Track where each book can be obtained (=:HOLDINGS:= — own
  collection, specific libraries) separately from shelf numbers
  (=:CALLNO:=).
- Download a book's Internet Archive scan as a local PDF, linked from
  the entry.
- Stable cite keys (=:CUSTOM_ID:=) generated per entry, collision-safe.

* Installation

Not yet on MELPA. Install from the repository URL with
=package-vc-install= — built in since Emacs 29.1 — then let
=use-package= configure it. This is the recommended form: it behaves
identically on Emacs 29 and 30.

#+begin_src emacs-lisp
(unless (package-installed-p 'org-reading-list)
  (package-vc-install "https://github.com/andapony/org-reading-list"))

(use-package org-reading-list
  :ensure nil)
;; ...add your configuration to the block above; see Configuration below.
#+end_src

=:ensure nil= keeps =use-package= from trying to fetch the package from
a package archive when =use-package-always-ensure= is set;
=package-vc-install= has already put it on the =load-path=. Given a
bare URL, =package-vc-install= tracks the default branch, so
=package-vc-upgrade= fast-forwards.

Requires Emacs 27.1+ and a recent Org. To install by hand instead,
clone the repository and either add it to your =load-path= or pass
=:load-path "/path/to/org-reading-list"= to the =use-package= form
(keeping =:ensure nil=).

** The =:vc= keyword on Emacs 30

On Emacs 30.1+, =use-package= understands the =:vc= keyword, so you can
fold the install into the declaration and drop the separate
=package-vc-install= call:

#+begin_src emacs-lisp
(use-package org-reading-list
  :vc (:url "https://github.com/andapony/org-reading-list"
       :rev :newest))
#+end_src

Keep =:rev :newest=: without it =:vc= checks out the latest release as
a detached HEAD, and =package-vc-upgrade= then silently does nothing —
its =git pull= has no branch to merge into. Tracking the tip keeps the
checkout on a branch, so upgrades fast-forward (the =package-vc-install=
form above already does this).

The =:vc= keyword is *not* recognized by the =use-package= bundled with
Emacs 29 — it raises "Unrecognized keyword: :vc". On Emacs 29 use the
=package-vc-install= form above.

* Configuration

The recommended configuration folds the options and the capture
template into the =use-package= block from [[*Installation][Installation]]:

#+begin_src emacs-lisp
(unless (package-installed-p 'org-reading-list)
  (package-vc-install "https://github.com/andapony/org-reading-list"))

(use-package org-reading-list
  :ensure nil
  :commands (org-reading-list-insert
             org-reading-list-loc-enrich
             org-reading-list-loc-tags
             org-reading-list-set-holdings
             org-reading-list-download-pdf)
  :custom
  (org-reading-list-file "~/org/reading-list.org")
  ;; Holdings codes for :HOLDINGS:/:CALLNO: completion. OWN and IA are
  ;; built in; add short, uppercase, stable codes for your libraries.
  (org-reading-list-holdings-codes '("OWN" "IA" "MILIB" "SFPL"))
  ;; Where org-reading-list-download-pdf stores Internet Archive scans.
  (org-reading-list-pdf-directory "~/books/pdfs/")
  ;; Cap on subject tags harvested from captured or fetched records.
  (org-reading-list-max-tags 6)
  :init
  ;; Register the capture template eagerly so its =r= key is live at
  ;; startup. The package itself still loads lazily — on the first
  ;; command above, or when the template fires (its helpers are
  ;; autoloaded).
  (add-to-list 'org-capture-templates
               '("r" "Book for the reading list" entry
                 (file+function org-reading-list-file
                                org-reading-list-goto-headline)
                 "%(org-reading-list-capture)" :empty-lines 1)))
#+end_src

=:commands= is what defers loading: without a deferral trigger
=use-package= would load the whole package at startup just to apply
=:custom=. The capture template goes in =:init= (which always runs)
rather than =:config= (which runs only after the package loads), so its
key is registered even while the package stays lazy.

Without =use-package=, set the options and register the template
directly:

#+begin_src emacs-lisp
(setq org-reading-list-file "~/org/reading-list.org"
      ;; Your libraries; OWN and IA are built in.
      org-reading-list-holdings-codes '("OWN" "IA" "MILIB" "SFPL")
      org-reading-list-pdf-directory "~/books/pdfs/")

(add-to-list 'org-capture-templates
             '("r" "Book for the reading list" entry
               (file+function org-reading-list-file
                              org-reading-list-goto-headline)
               "%(org-reading-list-capture)" :empty-lines 1))
#+end_src

Both entry points file under =org-reading-list-headline= (default
"Books", created if absent): =org-reading-list-insert= directly, and the
capture template via =org-reading-list-goto-headline= in its
=file+function= target. Change that one option and both follow.

If the Library of Congress SRU index stops matching, override
=org-reading-list-loc-sru-url= here too — see its docstring.

Suggested preamble for the reading-list file itself:

#+begin_example
,#+TITLE: Reading List
,#+TODO: TOREAD(t) READING(r) | READ(d) ABANDONED(x)
,#+COLUMNS: %TODO %DATE(Year) %AUTHOR(Author) %ITEM(Title) %HOLDINGS %CALLNO %ADDED
,* Books
#+end_example

** Link abbreviations

Two Org [[https://orgmode.org/manual/Link-Abbreviations.html][link abbreviations]] turn an identifier already in an entry
into a one-click lookup. Add them to the preamble of your
reading-list file:

#+begin_example
,#+LINK: ia https://archive.org/details/%s
,#+LINK: sfpl-isbn https://sfpl.bibliocommons.com/v2/search?searchType=isbn&query=%s
#+end_example

- =ia= — opens an Internet Archive item in the online reader, e.g.
  =[[ia:mountainsandmol00marrgoog]]= using the identifier captured in
  =:IA:=.
- =sfpl-isbn= — runs an ISBN search against the San Francisco Public
  Library catalog, e.g. =[[sfpl-isbn:9780252066313]]=, putting an
  availability check one click from any entry. Point it at whatever
  catalog you use.

* Usage

- =M-x org-reading-list-insert=: prompts for an ISBN, OL edition id,
  or OL URL and files a fully populated entry under the
  =org-reading-list-headline= heading (default "Books", created if
  absent) in =org-reading-list-file=, then shows it. The capture
  template does the same via =org-capture=, and also prompts for an
  optional "found via" source.
  Both entry points check for duplicates first — same ISBN or OLID,
  or same title and author (so reissues with a new publisher or year
  are caught) — and ask before adding; declining jumps to the
  existing entry (insert) or aborts (capture).
  When Open Library has no record for an ISBN or LCCN, the entry is
  built from the Library of Congress catalog instead (one SRU query;
  the LoC rate-limit note below applies). When Open Library *has* the
  record but holds no ISBN or LCCN — common for OLID/pre-ISBN
  lookups — the identifiers LoC has (LCCN/OCLC/LCC/DDC) are filled in
  from a title/author search, kept only when the author and year
  agree with Open Library's. Any LoC record consulted also seeds
  :ABSTRACT: from its MARC 520 summary, when it has one.
- =M-x org-reading-list-loc-enrich= on an entry: fills missing
  LCCN/OCLC/LCC/DDC and the :ABSTRACT: summary from the Library of
  Congress record (queried by ISBN, by LCCN for pre-ISBN books, or by
  :TITLE:+:AUTHOR: when the entry has neither identifier — guarded by
  author and year). =C-u= overwrites existing values — useful for
  refreshing entries captured
  from pre-publication CIP records once LoC completes them.
- =M-x org-reading-list-loc-tags=: adds the LoC subject headings as
  normalized tags (=C-u= replaces instead of merging). Prune to your
  own tag vocabulary afterward.
- =M-x org-reading-list-set-holdings=: records availability with
  completion over your holdings codes.
- =M-x org-reading-list-download-pdf=: for entries with an =:IA:=
  identifier, downloads the Internet Archive PDF into
  =org-reading-list-pdf-directory=, links it from =:LOCALFILE:=, and adds
  =OWN (pdf)= to =:HOLDINGS:=.

** Controlled-vocabulary tags

The reading-list file's own =#+TAGS:= line defines the controlled
vocabulary.  Raw tags harvested from Open Library or the Library of
Congress are normalized but may not yet match it — use the tools below
to reconcile them.

=org-reading-list-tag-rewrites= is a per-file alist mapping raw (or
variant) tags to their vocabulary equivalent, or to =nil= to drop them
entirely.  Set it as a file-local variable or in =.dir-locals.el=:

#+begin_src emacs-lisp
;; In the reading-list file's local variables or .dir-locals.el:
((org-mode . ((org-reading-list-tag-rewrites
               . (("gold_discoveries" . "gold_rush")
                  ("vigilance_committees" . "vigilance")
                  ("history" . nil))))))   ; nil = drop
#+end_src

The variable is marked =safe-local-variable= so Emacs will not prompt
when the rewrite map is set this way.

- =M-x org-reading-list-fetch-subjects=: populates =:SUBJECTS:= for the
  entry at point by querying Open Library, the LC Catalog, MILibrary (when
  loaded), and any other registered source, unioning the normalized subjects
  they return.  It then re-derives the heading tags from the stored
  subjects through the controlled vocabulary, as capture does.  With
  =C-u=, does this for every book entry in the buffer after prompting for
  confirmation.  Entries from which no source returns subjects are left
  unchanged.
- =M-x org-reading-list-lint-tags=: a preview (dry run) — shows for
  each entry the rewrites and drops that =preen= would apply, and flags
  entries with fewer than =org-reading-list-tag-min= tags (default 1) or
  without a =:SUBJECTS:= property.  Nothing is modified.
- =M-x org-reading-list-preen-tags=: re-derives the entry's Org tags from
  its =:SUBJECTS:= property by applying the rewrite map, then sets the
  headline tags.  With =C-u=, preens every book entry in the buffer after
  prompting for confirmation.  Capture always projects =:SUBJECTS:= to
  tags on filing.
- =org-reading-list-tag-infer-function= (default =nil=): a hook for
  inferring tags for entries below the minimum.  Live LLM inference via
  gptel is planned and will plug in here.

** MILibrary search

Load the optional companion file to enable direct search of the
Mechanics' Institute Library catalog (milibrary.org):

#+begin_src emacs-lisp
(require 'org-reading-list-mi)
#+end_src

- =M-x org-reading-list-mi-search=: searches milibrary.org by title
  (a prefix argument lets you choose author, keyword, or ISBN instead),
  presents matching results, and either captures a new entry or updates
  an existing one — adding =MILIB= to =:HOLDINGS:= and filling
  =:CALLNO: MILIB …= from the MI catalog's MARC record.
- =M-x org-reading-list-mi-enrich=: enriches the Org entry at point
  from its MILibrary record: attaches =MILIB= holdings and call number,
  fills empty fields from MARC, and offers to refresh any differing
  fields.

* Citing books from org-chronicle

When [[https://github.com/andapony/org-chronicle][org-chronicle]] is
loaded, =M-x org-chronicle-add-source= completes over this reading list
and files a citation as an =orl:= link, e.g.

#+begin_example
:SOURCES: [[orl:foote1963][Foote, The Civil War (1963)]] p.412
#+end_example

The =orl:= link type is provided here: following it jumps to the entry
whose =:CUSTOM_ID:= matches, and it exports to the book's label.  Only
entries that have a =:CUSTOM_ID:= are offered for completion — capture
assigns one automatically, but legacy or hand-written entries may lack
it.  Run =M-x org-reading-list-ensure-citekeys= in the reading-list
buffer once to stamp citekeys on every keyless entry and make them
citable.  =M-x org-chronicle-book-citations= (from org-chronicle), run on
an entry here, lists the chronicle events that cite that book.

* Etiquette and caveats

- The Library of Congress asks automated clients of lx2.loc.gov to
  stay under ~10 requests/minute. The commands here make one request
  per invocation; throttle any batch use yourself.
- Open Library author names arrive in direct order and are inverted
  heuristically; check compound surnames.
- LoC's post-FOLIO SRU index support is in flux; if =bath.isbn= stops
  matching, see =org-reading-list-loc-sru-url=.

ERT suite. Tests are offline — pure functions only.
